# 功能完整性与答辩可信度完善设计

## 1. 目标与背景

本阶段目标是提高毕业设计程序的功能可信度和答辩可解释性，让“需求文档、实际代码、运行结果、测试证据”保持一致。

当前项目已经具备 Vue 3 前端、Spring Boot 后端、MySQL 数据层和 Python 采集/清洗/预测脚本，主要业务页面和接口基本存在。本阶段不扩大为新的平台建设，不引入 Redis、EasyExcel 或 PDF 生成等大组件，优先完善已有核心闭环。

### 成功标准

- 登录、JWT 鉴权、管理员路由和管理员高校 CRUD 能被稳定演示和验证。
- 高校查询、详情、对比、志愿推荐、预测、大屏统计等已有核心路径使用真实接口数据，不能静默展示未标识的模拟数据。
- 预测页面的指标、历史数据和预测数据能够说明来源、时间窗口和“预测”含义。
- 后端拥有覆盖认证、权限、核心查询和关键业务校验的自动化测试；前端和 Python 工具链至少完成构建/编译检查。
- README 与《需求分析与技术方案.md》明确区分“已实现”“演示模式能力”和“后续扩展”。
- 不破坏当前工作区已有未提交改动，不回滚用户现有截图、主题和页面调整。

## 2. 范围

### 本阶段包含

1. 核心业务接口与页面的数据来源核对。
2. 模拟兜底数据的显式化或移除，保留必要的空状态和错误状态。
3. 预测指标与预测结果的一致性改造，至少保留可追溯的模型名称、训练窗口、预测窗口和数据更新时间。
4. 认证、管理员权限、核心查询和推荐/预测输入校验测试。
5. 配置安全收口：数据库连接信息和 JWT 密钥支持环境变量覆盖，默认配置不作为生产凭据。
6. README、需求文档和答辩说明的事实校准。

### 本阶段不包含

- Excel/PDF 完整导入导出功能。
- 个人资料编辑和修改密码流程。
- Redis 缓存、分布式任务调度和全文检索。
- 大规模爬虫源扩展、数据库重构或前端整体换肤。
- 删除现有工作区文件、清理截图、回滚未提交修改或提交 Git 历史。

未包含的功能保留为后续扩展，并从“已完成能力”描述中移除或标注为规划项。

## 3. 当前问题基线

根据当前代码和需求文档核对，存在以下事实差异：

- 管理员页面的批量导入按钮当前只显示提示，尚未执行导入；导出按钮生成的是当前页 CSV，并非 EasyExcel 文件。
- 用户认证接口目前包含登录、注册和用户信息查询，没有个人信息编辑或修改密码接口。
- 后端依赖中没有 Redis、EasyExcel、PDF 相关库，但 README 和需求文档将这些技术写成现有能力。
- 预测服务从 `prediction_result` 读取部分预测值，但模型指标包含硬编码值，历史序列和缺失预测值也有服务层默认值。
- 前端多个页面存在本地默认数据或请求失败兜底，需要明确区分真实接口数据、演示数据和空状态。
- 后端当前自动化测试数量较少，前端没有独立的接口/组件测试。

## 4. 设计方案

### 4.1 数据来源状态模型

前端页面加载数据时统一使用以下状态：

```text
加载中 -> 成功(真实接口数据)
      -> 空数据(接口成功但没有记录)
      -> 失败(接口异常，可重试)
      -> 演示数据(仅当显式 demo 配置开启时)
```

默认情况下，请求失败不再静默切换为看似真实的模拟数据。若在线演示必须提供稳定画面，则由后端演示模式或前端明确的演示标识提供数据，并在页面上显示“演示数据/最后更新时间”等提示。

### 4.2 预测数据一致性

保留现有 `prediction_result` 表作为预测序列存储，新增一套可追溯的模型元数据来源。优先采用轻量方案：

- 在后端增加模型元数据服务对象，集中定义模型名称、训练窗口、预测窗口、指标和数据更新时间。
- 预测脚本训练完成时输出与服务对象相同格式的指标 JSON/日志，并在接口层统一返回。
- `getTrendsData()` 对缺失预测值返回明确的空值或错误提示，不再用静默默认数字填充。
- 页面区分历史实线和预测虚线，并显示“预测值不等于实际统计值”的说明。

若后续需要完全由数据库驱动，再将模型元数据落入单独表；本阶段不为此引入复杂的模型管理系统。

### 4.3 权限与配置

- 保持当前 JWT 无状态鉴权模型。
- 管理员高校 CRUD 继续使用 `ROLE_ADMIN` 保护。
- 公开 GET 查询继续保持可访问，但写操作必须经过 Security 和演示模式拦截器双重约束。
- `application.yml` 和 Python 脚本保留本地开发默认值的兼容能力，同时支持环境变量覆盖，并在文档中明确默认值仅用于本地演示。
- 不在日志、测试输出和交付说明中打印密码、JWT 密钥或完整数据库连接凭据。

### 4.4 测试策略

后端按风险分层增加测试：

1. Service 单元测试：推荐结果边界、预测缺失值、查询条件校验。
2. Controller/Web 层测试：登录成功/失败、未登录访问管理员接口、普通用户访问管理员接口、管理员 CRUD。
3. 数据契约测试：关键返回结构与前端 API 类型一致，错误响应使用统一 `Result` 格式。

验证命令保持简单可复现：

- `npm.cmd run build`
- `mvn.cmd test`
- `py -3 -m compileall -q crawler`

需要数据库的测试使用当前本地测试数据库或已有测试配置，不进行真实生产数据写入。若环境缺失，则明确记录为“未验证”，不将构建通过等同于接口全链路通过。

## 5. 分阶段交付

### 阶段一：事实校准与数据状态

- 清点各页面的真实接口、默认数据和失败兜底。
- 统一页面加载、空状态、错误重试和演示标识。
- 修正预测服务的硬编码指标和静默默认值。

### 阶段二：核心安全与业务测试

- 增加认证、权限、管理员 CRUD、推荐和预测的测试。
- 检查 DTO 校验、异常响应和管理员写操作。
- 校准配置文件的环境变量读取。

### 阶段三：文档与答辩证据

- 更新 README 和需求方案的“已实现/规划中”矩阵。
- 增加本地启动、测试结果、数据来源和演示模式说明。
- 整理一条可复述的数据链路：采集/初始化数据 → MySQL → Spring Boot API → Vue/ECharts 页面。

## 6. 风险与取舍

- 取消静默模拟兜底后，数据库不可用时页面可能显示空状态；这是为了避免答辩时把模拟数据误说成真实数据，必须提供清晰错误提示和演示模式说明。
- 预测指标完全动态化需要调整 Python 与 Java 的接口边界；本阶段采用集中元数据和明确默认策略，控制改动范围。
- 配置安全改造可能影响 Render 或本地启动；修改后必须分别验证本地默认配置和环境变量配置。
- 当前工作区有大量未提交修改，所有编辑仅限本设计涉及的文件，修改前先检查差异，避免覆盖既有成果。

## 7. 答辩表达口径

本阶段完成后，项目可以真实表述为：

> 平台围绕高校基础数据查询、统计分析、院校对比、志愿推荐和趋势预测构建了前后端闭环；通过 JWT 和角色权限控制管理员写操作，并使用统一接口响应、输入校验和自动化测试保证核心功能可验证。Excel/PDF 报表、Redis 缓存和个人资料维护属于后续扩展，不作为本阶段已完成能力陈述。

不得表述为已经完成 EasyExcel 百万级导入导出、Redis 高并发缓存或 PDF 报告生成，除非后续确实完成并通过独立验证。
